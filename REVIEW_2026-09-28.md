# docxkit — architecture review, 2026-09-28

The fourth review, and a different altitude from the three before it
([`08-15`](REVIEW_2026-08-15.md), [`09-01`](REVIEW_2026-09-01.md),
[`09-03`](REVIEW_2026-09-03.md)). Those walked the import graph, the
declared API and the oldest seams. This one asks the architect's
questions: is the SUBSTRATE right, do results have a contract, where does
policy live, what does the quality apparatus cost against what it finds,
and what does a consumer get to depend on. Defects it found are filed in
`BACKLOG.md` under `## Open`, marked **→ BACKLOG** below with their
severity on that file's scale.

**Measured on** `8b838f1`, Python 3.14.7, this machine. **Tools:** AST
walks over `src/`, `tests/` and `tools/` (import graph with deferred
imports split out, raise sites, result types, signatures, regex call
sites classified markup vs prose); `git log --numstat` since 08-29; `gh
run list` over 200 CI runs; the gate-timing history in `.timings/` (132
chains); a hand classification of the 384 fixed entries in
`BACKLOG-ARCHIVE.md`; one probe of a real 434 KB redline build and one of
a 6.48 MB `document.xml`. The review's scripts are session scratch, not
committed. Every finding marked → BACKLOG was reproduced against the live
tree before it was filed.

**Scale:** 70 modules, 46,246 source lines (+34 % since 09-03, +39 %
since the `v1.0.0` tag); 116,683 test lines, 9,067 tests collected;
`tools/` 10,093 lines in 28 scripts; 562 commits since 08-29.

**Verdict.** The package is in better health than its size suggests —
layering holds, the write path is atomic, 90 % of raises are in the
package's own error family, CI is green — and the recurring defect
families have names, gates and a history. What this pass finds is that
the **architecture has not been re-planned since the package was a
fifth of this size**. Three decisions that were right at 10k lines are
now where the cost is: markup read by hundreds of independent regexes
rather than one lexer; results that are ad-hoc bags of lists rather
than a contract; and a quality apparatus that has grown faster than the
code it guards (31 % of commits touch `src/`). None needs a rewrite.
Each has an incremental path that starts with primitives the package
already has.

## 1. The substrate: markup read by hundreds of regexes → BACKLOG S2 (one instance)

**Measured.** 554 `re.*` call sites in `src/`; about **369 read markup**
and 185 read prose, across 35 of the 46 modules that use `re`. Only 48
of the markup patterns (13 %) are in `_xml.py`. There are also 102
plain-string reads of markup (`in`, `find`, `index`), 64 lazy
`.*?</w:X>` patterns in 20 modules, and `PARA_RE` alone has 104 uses in
25 modules. lxml is imported in 10 modules — readers, the XSLT for
maths, the accept/reject simulation — and writes a deliverable in one
place (`placement.py:999`, `:1237`). There is **no central tokenizer or
span model.**

**What it costs.** Of the 384 fixed entries in the archive, 35 (9.1 %)
are the markup-spelling family proper — self-closing and empty
elements, ` />`, attribute order, prefix names, nesting and depth
pairing, a property present twice — and 67 (17.4 %) are XML-substrate
causes once offset/splice errors and schema child order are counted.
That UNDERSTATES it by defect count: single entries carry four, eight
and thirty-one commits.

**The mitigation is a gate, and a gate is not a design.**
`tests/test_regex_registry.py` (1,994 lines, 586 tests, 70 declared
exemptions, two fact tables) enforces six spelling rules over every
pattern it can fold. It is good work and it catches what it knows. It
cannot see depth pairing, a pattern that admits NO attributes,
first-close pairing through `str.index`, lxml sites, or a duplicated
property — and the live proof is `find.table_spans` (`find.py:245`), a
public function with both of the defects its twin
`_table_core._table_spans` documents fixing on 09-17. Reproduced: on an
outer table holding an inner one, it returns an unbalanced outer span
ending at the INNER close, lists the inner as a second table, and does
not see a table whose tag carries an attribute. **→ BACKLOG S2.**

Candidates of the same shape, not reproduced end to end:
`_compare_read.py:64/331` and `crossrefs.py:120/127` read
`<w:rPr>(.*?)</w:rPr>` without `live_properties`, and `sections.py:192`
the same of `pPr`. And `run_open_before`'s docstring (`_xml.py:840`)
says it returns the run CONTAINING a position; it returns the last run
that OPENS before it — the neighbour-versus-enclosing trap.

**The rationale for string surgery is right, and is only half written
down.** README, `package.py` and `edit.py` justify it against
python-docx: untouched PARTS survive byte for byte. The stronger reason
— bytes outside an edit INSIDE a part stay identical, so Word's Compare
and a round-to-round diff see only the edit — is written nowhere and
tested nowhere. lxml round-tripping would lose it (` />` → `/>`, an
empty paired element collapses, the offsets the papers splice at move).

**Recommendation — a span lexer under the same byte-splice API.** One
tokenizer in `_xml` that yields each tag once — start, end, name,
parsed attributes, open/close/empty, depth — handling comments, CDATA
and a `>` inside a quoted value. The primitives the package already
grew are its first clients and keep their signatures: `element_spans`
(23 uses), `own_properties` (50), `live_properties` (37), `fields` (19),
`matching_close` (7), `run_open_before` (11). Each re-scans the string
with its own pattern today. Order of work:

1. Fix `find.table_spans`; add registry rules for "opening tag admits no
   attributes" and "lazy pattern over an element that nests" (`tbl`,
   `tc`, `tr`, `rPr`, `pPr`, `sdt`, `hyperlink`).
2. The lexer, and the primitives re-implemented over it; the old and new
   diffed over the corpus with `writer_oracle` and `sweep` — this
   repository is unusually well equipped to prove a substrate change.
3. A per-string cached index and a batch splice applied back to front.
   Today `batch` pays `PARA_RE` over the whole part plus `visible_text`
   on every paragraph PER EDIT, twice (preflight and apply): 41.8 ms per
   locate on a 6.48 MB part, ~8 s of locating per 100 edits. Not a
   problem at the median manuscript; the shape is O(k·n).
4. Migrate by regex density × defect history (`hygiene` 37 patterns,
   `_table_layout` 29, `styles` 25, then `comments`, `crossrefs`,
   `edit`, `sections`, `_cite_repair`), and then let the registry REFUSE
   element pairing outside `_xml`. That last step is what turns a
   policed convention into a design.

Estimated 250–300 call sites route through a span API; the 100–150
attribute reads can stay regexes over a tag the lexer has already
isolated. **Write the intra-part byte invariant down and give it a
test** before step 2 — it is the property the migration must keep.

## 2. Results have no contract → BACKLOG S1, S2

The package's most repeated lesson is "a report that reads as success".
The architecture does not help it.

**Measured.** 108 dataclass / NamedTuple / TypedDict result-shaped
types, ~52 of them results or findings (26 named `*Report`). None shares
a base or a Protocol; none carries a severity. Names collide
(`FitReport`, `HouseReport`, `Verdict`, `Sheet`, `Style` each twice).
Truthiness runs BOTH ways: `refstyle`'s reports are truthy when
something changed, even with `refused` non-empty; `RowsReport.__bool__`
is truthy when the check PASSED. 14 of 46 public check functions return
`list[str]`.

`BuildReport` is the instance that matters: 17 list fields, no `ok`,
and a `format()` that prints six of them and none of the refusal lists.
Which lists block is known in exactly one place,
`_tracked_report._refuse_accept_side`. Every other consumer re-derives
it — and `compare-probe` re-derived it wrong: it prints "both views
reproduce their documents" and exits 0 without reading
`accepted_losses` or `orphan_notes`, which `build` fills on every run
and refuses on. **→ BACKLOG S1.**

**Exit codes collide.** 2 is MathResolved, validate-aborted, survey
unreadable, argparse's usage error and five commands' own meanings; 3
is BaselinePending and "Word could not open"; a plain `DocxKitError`
exits 1, the same as "findings present". A non-family exception (15
bare `ValueError`s, `int()` of a config value, a raw `ZipFile` in
`ingest`) is a traceback.

**Config is typed but not validated.** `Paper` is a frozen dataclass;
the values reach it through `tuple()`/`bool()`/`int()` of whatever TOML
held. `render_math = "no"` is True; `commands = "pytest -q"` is ten
gates. **→ BACKLOG S2.**

**Recommendation.** One `Finding(code, severity, part, where, message)`
and a `Report` Protocol — `findings`, `ok`, `blocking()` — in the bottom
layer; `format()` and the CLI's exit code DERIVED from it rather than
rebuilt per command; one exit-code enum in `errors.py` with refusals and
verdicts in separate ranges, and `main()` wrapping anything outside the
family. Migrate the reports the CLI prints first (`BuildReport`,
`validate`, `lint`, `house`, `refstyle`); ban `__bool__` on reports. The
config validation is the same idea at the input edge.

## 3. Policy that lives in the CLI

The 09-01 review found protocol decisions in `cli.py`; they have been
moved out where it said. New policy keeps arriving there, and the most
expensive instance is the WRITE.

**Measured.** `cli._save` (`:898`) runs `preserve_space`, refuses on lint,
backs up into the rescue directory, then writes. The public
`package.edit_in_place` — the entry point the papers are told to use —
does none of that. `lint` findings are merged with `styles` findings in
`cli._raised_prose`, because the layering forbids the sibling import; a
library caller of `lint_parts` never sees the merged set. `cli.py` is
3,086 lines (2,357 at the tag), 44 commands; argparse is 20 % of it,
command bodies 48 %, helpers 25 % of which ~250 lines are policy
(`_paper_gates`, `_render`'s math anchors, `init`'s rewrite detection
through private `_CONFIG`/`_DIR`, `cmd_revision_ingest` deriving its own
exit code).

**The one cycle is one helper.** With deferred imports counted, the only
strongly connected set is {cli, compare, revision}, and its only upward
edge is `compare.py:249` — `compare.main`, a second entry point
duplicating `docxkit compare`, importing `cli._write_json`.

**Recommendation.** `package.save(path, parts, *, backup_into=None,
allow_existing_lint=False) -> SaveReport` in a layer above `lint` and
`edit`; `edit_in_place` calls it, the CLI prints it. Move `_write_json`
to `console` (or drop `compare.main`) and empty `_CYCLE`. Split `cli`
into a package — parser, commands, revision commands — when it next
grows, not before; its size is a symptom of policy arriving, not a
cause.

## 4. CI: the bill is one job

**Measured** over 200 push runs, 08-29 → 09-27. 3,982 billed minutes —
about twice the 2,000 free private minutes, the reason the repository is
public. The `mutations` job is **2,860 (72 %)**: 42 curated mutations,
each a full-suite run, median 14.9 min, on every push. No
`paths-ignore`: 122 of 200 runs changed nothing under `src/` and cost
2,369 minutes; 29 docs-only pushes cost 583. The `test` job runs the
suite TWICE — pytest (77 s) then `coverage_floor.py`, which runs it
again under coverage (73 s); the local chain was changed to one run and
CI never was. CI does not run `optionals`, `unrun`, `claims`,
`committed` or `sweep`.

Locally the green chain's daily median went 49 s (09-06) → 149 s
(09-26): pytest 31 → 79 s, plus `sweep` running since 09-25. In the
latest run 62.7 of the 67.6 s spent in the 25 slowest tests are tests
of the TOOLING (`stale_figures`, `mutation_session`, `kill_check`, …).
`gates.py`'s docstring still says nine gates; it runs twelve.
**→ BACKLOG S4.**

**Recommendation.** `paths-ignore: ['**.md', 'docs/**',
'tools/equivalents.toml']`; floors read the pytest run's coverage file;
`mutations` to a nightly/`workflow_dispatch` job, or each curated
mutation run against its `harness_map` tests rather than the suite
(~15 → ~2 min). Together: 3–4 min per source push, ~600–900 min a
month. Mark tooling tests `-m tooling` and run them when `tools/`
changes.

## 5. Versioning: the consumers have nothing to pin

**Measured.** `version = "1.0.0"` since 08-08; one tag, `v1.0.0` on
09-01, 548 commits ago. The `api` gate diffs against the latest tag, so
its baseline is four weeks old and every addition since reads as new.
Public names in `__all__`: 626 → 772, **none removed**. Cross-module
imports of private names: 115 (the 08-15 review counted 7 edges). Four
facades re-export 104 `_X as _X` names (revision 43, citations 35,
tracked 14, tables 12); ~63 have no importer found. `tools/consumers.txt`
dates from 09-02: a scan of the corpus now finds 193 imported (module,
name) pairs against 143 recorded, and papers importing
`tracked._simulate`, `tables._table_spans`, `_table_layout._column_needs`.

Nine papers import from an editable install, so every commit to master
is a release to all of them at once. That is a legitimate choice for a
single maintainer — but then the gates are the ONLY contract, and the
one that speaks for the consumer is measuring against a month-old
photograph.

**Recommendation.** Tag on every consumer-visible change (CalVer —
`2026.9.28` — suits a package whose releases are days); refresh the
consumer snapshot and make `consumers --check` a gate wherever a corpus
is set; resolve whole-module imports' attribute use through the AST.
Make the private names the papers actually use public under their
public names — `accepted_view(parts)` / `rejected_view(parts)` for
`_simulate` first, which also removes the name clash with
`revisions._simulate` — and delete the unimported private re-exports.

## 6. The apparatus is a second product

**Measured.** Of 562 commits since 08-29, **31 % touch `src/`**; 34 % are
docs-only, 21 % change tests without source (largely kill rounds), 13 %
touch only tools and meta. By line churn: tests 37 %, docs 31 %, src
21 %, tools 10 %. `BACKLOG*.md` was touched by more commits (215) than
`src/` (172). `equivalents.toml` holds 1,261 argued claims over 55
modules and took 94 commits. 1,121 tests (12 %) check the source's
SHAPE rather than run it; 818 test `tools/`. `pyproject.toml` is 331
comment lines to 134 of settings. `BACKLOG-ARCHIVE.md` is 17,502 lines.

**What finds the defects.** Of the 116 fixed product S1/S2 entries whose
finder is stated: real paper use 63, mutation-survivor rounds 35, code
review 9, gates/CI 4, corpus sweep/oracle 4, property tests 1. Survivor
READING rounds are not tapering (19 product defects fixed 09-16..30
against 7 in 09-01..15) — but 46 of 65 measured modules are already at
≤ 2 % survival and 66 of 68 stored figures are stale. The defects come
from reading survivors, not from the percentage.

**Judgement.** Keep what finds defects: paper use, survivor-reading
rounds, both type checkers, pytest, `api`, `deps`. The diminishing
returns are the bookkeeping around them — re-measuring modules at 0–2 %,
the claims ledger's upkeep on every fix, figures hand-copied into
prose, and meta-gates that test the apparatus (`claims`, `unrun`,
`backlog_status`). Each was justified by a real incident; together they
are an eighth of the commits and the slowest tests in the suite. Fold
`claims`, `unrun` and `floors` into one apparatus check that runs when
`tools/` or `tests/` change; let `stale_figures --figures` be the only
place a figure lives.

**What is missing is where the defects come from.** Real manuscripts
found more S1/S2s than every gate together, and not one test holds a
real manuscript: every document in the suite is synthetic, and the
corpus `sweep` was skipped in 77 of 81 chains. Add **golden end-to-end
tests** on three to five frozen, anonymised manuscripts (input `.docx`
→ expected text, structure counts and redline census), **property tests
over corpus-derived XML** for the mutators (idempotence, no text lost,
accept∘build = clean), and one **performance regression** on a large
document — timings are recorded for the gates and never for the
library.

## 7. Granularity, data flow and house style

* **`_table_layout.py`** (2,003 lines) holds six banner-separated
  concerns — fitting with font metrics, decimals, regrid, stars,
  rules/booktabs, house. Split the metrics-and-fit half out first.
  **`edit.py`** carries ~590 lines of link surgery (`954–1540`) while
  link logic also lives in `_xml`, `citations` and `crossrefs`: gather a
  `links` module. **`tracked.build`** is 389 lines (263 on 09-01).
  `_xml` (64 exported names, 44 importers) is a cohesive kernel — leave it.
* **One build computes the same thing several times.** A `revision
  build` unzips `prev.docx` 8 times, re-reads its output 3 times, runs
  the accept simulation 3 times and reject 3 times, and calls
  `untracked()` again on the written file after `tracked.build` stored
  it. Cost is not the issue — 0.13 s of offline gates against 40–141 s
  in Word — the issue is two sources of truth: the caller recomputes
  instead of reading the report. An immutable per-package view (decoded
  parts, accepted and rejected views, cached) passed down the pipeline
  fixes both.
* **Three mutation styles, unnamed.** 38 functions mutate `Parts` in
  place with 15 different return types; three copy and return. Pick one
  rule (mutators take `parts`, return `None` or a report) and lint it.
  158 `.decode(` calls in 30 modules each choose a policy (132 strict,
  22 `"replace"`), so a malformed part fails in one command and passes
  in another — decode once, at `read_parts`' edge.
* **House style is data, in four places, and a paper cannot choose it**:
  `house.Rules`, `_table_layout.house(font="Arial Narrow")`,
  `footnotes.set_font` (Times New Roman 10) and `refstyle.HOUSE`;
  `paper.toml` has no `[house]` section. One `HouseStyle` object and a
  section to name it.
* **The workflow's errors live in the library's bottom layer.**
  `errors.py` carries `ProtocolError` and five workflow subclasses with
  CLI exit codes, raised only from `revision/` and `cli`. Move them to
  `revision/_errors` and re-export.

## Non-findings — measured, and not worth a batch

* **Layering holds.** With facade halves given their facade's layer and
  deferred imports counted, zero violations; the only cycle is §3's one
  helper. Of 103 deferred internal imports, 80 are the CLI's lazy
  per-command loading (deliberate), 12 are redundant (the module already
  imports the target at top level) and ~7 have no evident reason — tidy
  when passing, not a batch.
* **The write path is sound.** `read_parts` maps zip and OS errors to
  `PackageError` and retries a locked file; `tracked.build` stages and
  replaces only after every gate passes.
* **The error family is used.** 322 of 356 raise sites; all 25 `assert`s
  are type narrowing, not validation. The 20 broad `except Exception`
  sites are COM and batch boundaries, bar one: `revision/_validate.py:424`
  reports a `WordTimeout` or a programming error as "Word could not
  open" (exit 3). Worth narrowing when next touched.
* **Caches are safe.** All eight `lru_cache`s take and return immutable
  values; the global state is `word`'s shared instance and watchdog and
  the XSLT cache, all deliberate.
* **Library and workflow separate cleanly at the import level.** Only
  `cli` imports `revision`; no library module mentions `log.md` or a
  ledger.
* **Performance.** Not a problem at the median manuscript; §1's O(k·n)
  is the only shape worth fixing, and it falls out of the lexer.
