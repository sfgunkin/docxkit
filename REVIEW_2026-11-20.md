# docxkit — architecture review, 2026-11-20

An architect's read of the package as a whole, not a diff review. It covers
what changed since `REVIEW_2026-10-24.md` (87 commits, about 5,000 source
lines) and does not reopen what the earlier seven settled. Static measures
were taken over `src/docxkit` at `09fa037` (74 modules, about 53,000 source
lines, 129,000 test lines). Nothing in the papers was touched.

**Verdict.** Healthy for its size. The debt is in one place, the way a
redline build is assembled: one long function whose policy is a set of
booleans, a repair pipeline nobody declared, and a reject-side judgment
orchestrated twice.

## What holds

- **No import cycles.** Fan-in goes to a small core: `_xml` (54 importers),
  `errors` (42), the package itself (27).
- **The CLI only prints.** Engines decide, and `validate`'s exit code is
  `report.exit_code`.
- **Writers are consistent.** All 31 public functions that write into a
  `parts` argument change it in place. The one copy-then-write is
  `placement.place`, and it returns the copy.
- **Testing depth.** 2.4 test lines per source line, and the gate chain
  measures itself (`unrun`, `reach`, `claims`).
- **Settled questions stay settled.** XML is still read with regexes (648
  calls against 216 lxml calls). That was measured and kept on 2026-09-28,
  and nothing since argues for reopening it.

## Findings

| # | Sev | Where | What |
|---|---|---|---|
| 1 | S4 | `tracked.py:799` | `build` is 377 lines with 20 parameters, 10 of them booleans that switch refusals off; the reject-side judgment is orchestrated again in `revision/_validate.py` |
| 2 | S4 | `tracked.py:1007–1125` | the post-Compare repairs are an undeclared pipeline: order by line position, each proving its own safety its own way |
| 3 | S4 | `tools/gates.py` | `reach` (2 s, static) runs after the 4-minute suite, so a new module learns it needs an oracle only on a second full run |
| 4 | — | tags | 33 commits since `v2026.11.9.1`, among them changes a paper meets: the LATE MARKER exit code, the `replace_in_para` refusal, the bookmark replant |
| 5 | — | everywhere | prose is 41% of source lines, unchanged since REVIEW_2026-10-12 #5 (42%); recorded, not argued again |

**1. One function holds the pipeline and the policy.** `tracked.build`
runs Compare, repairs, judges, publishes and stamps in one body. Whether a
finding refuses is set by `reject_check`, `accept_check`, `lint_check`,
`force` and `verify_in_word`, so "who may skip which refusal" is spread
over call sites. The compare-probe turns every check off and forces. The
protocol turns the reject refusal off (`revision/_build.py:425`) and leaves
it to `revision validate`, which calls the same five checkers in its own
order (`untracked`, `structure_counts`, `bookmark_changes`,
`inserted_only_bookmarks`, `final_paragraph_cause`). A new cause is wired
twice: `e810cc7` touched both `tracked.py` and `_validate.py` for one
cause. No case of the two disagreeing was found; it is a risk, not a
defect. *Remedy:* stages (compare, repair, judge, publish), one reject-side
judge both callers use, and a policy value with three presets (direct,
protocol, probe). `force` and `reject_check` stay as aliases: paper scripts
pass `force=True` ten times and `reject_check=False` twice.

**2. The repairs have no declared order or invariant.** Seven passes run
before the gates and `restore_math_glyphs` after them. `return_note_spaces`
keeps a candidate if the count of paragraphs that do not accept correctly
falls; `replant_reinserted_bookmarks` (`a7ccbbb`) keeps one if both views'
visible text is unchanged. Each pass invented its rule. *Remedy:* a list of
passes, each naming the invariant it keeps (for instance "the rejected text
is unchanged"), checked centrally after each one. It also says which pass to
blame when a gate fails later. Do it with 1: same function.

**3. One static gate stands behind the suite.** Adding `_tracked_replant`
(206 lines) meant entries in seven places besides its code and test: two
harness lists and the facade in `harness_map.py`, the regex registry's
not-exercised list, `VALUES` in `test_value_types.py`, the README module
table, and a sweep routine. The first five are tests and surface together
in one pytest run; the extra runs there came from fixing one entry exposing
the next, which no order prevents. The sweep routine is asked for by
`reach`, which was ninth in the chain, behind the suite. `optionals` already
sits in front of the suite for the same reason ("costs two seconds and
answers about the source alone"). *Remedy:* move `reach` there.

**4. Tag.** `api` diffs against the latest tag, so every review and every
breakage verdict measures against the 11-09 surface. CONTRIBUTING asks for
a tag on every change a paper can see.

**Smaller.** `cli.build_parser` is 562 lines; each command's options
belong next to its command function. The 10-12 ask for a Word oracle on the
reject view is half met by `tools/view_oracle.py --word`, which no gate
runs.
