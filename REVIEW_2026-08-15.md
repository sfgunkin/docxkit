# docxkit — structural review, 2026-08-15

Not a defect list. `BACKLOG.md` is where defects go, and everything here
that belongs there is marked **→ BACKLOG**. This is the shape of the
package: what is coupled to what, what is duplicated, what is slow, and —
as often — what LOOKS like a problem and measures as nothing.

Nothing in here was implemented. Where a fix is suggested the effort and
the risk are stated so the batch can be planned rather than started.

## 1. The regex registry, and which half of it actually bites

**Census.** 158 compiled patterns, 157 distinct — so almost nothing is a
literal copy. But grouped by the ELEMENT they match, 22 elements have
more than one spelling:

```
  <w:p>       <w:p\b[^>]*(?<!/)>.*?</w:p>        _xml.py:116     (self-closing-safe)
              <w:p[ >].*?</w:p>                  _compare_read.py:36  (safe by accident of spelling)
              <w:p\b[^>]*>                       crossrefs.py:100     (NOT safe)
              <w:p [^>]*w14:paraId="..."         comments.py:467
  <w:r>       <w:r\b[^>]*>.*?</w:r>              _xml.py:131          (NOT safe)
              <w:r\b[^>]*>(.*?)</w:r>            _compare_read.py:38  (NOT safe)
              <w:r\b[^>]*>                       _xml.py:144          (NOT safe)
              <w:r(?:\s[^>]*)?>                  comments.py:470      (safe)
  <m:oMath>   <m:oMath>…  /  <m:oMath\b… /  <m:oMath\b[^>]*>…    3 modules
  <w:sz>      <w:sz w:val="(\d+)"/>  vs  <w:sz\b[^>]*w:val="(\d+)"[^>]*/>
  … and 18 more (w:rStyle ×3, w:pStyle ×2, w:rPr ×3, w:t ×3, w:tr ×2,
    w:gridCol ×2, w:hyperlink ×4, w:vertAlign ×2, w:pgSz ×2, …)
```

Exactly one pattern is compiled twice verbatim: the footnote element, in
`footnotes.py:51` and `revision.py:799`.

**Corpus scan settles which divergences matter.** 899 manuscripts under
`F:\onedrive\__documents`, `word/document.xml` each:

```
   32 / 899   self-closing <w:p/>
   28 / 899   self-closing <w:r/>
    0 / 899   <m:oMath with attributes
    0 / 899   <w:pStyle with an attribute before w:val
    0 / 899   <w:sz   with an attribute before w:val
    0 / 899   <w:sz   with an extra attribute after w:val
    0 / 899   <w:rStyle with an attribute before w:val
    0 / 899   <w:tc  with attributes
    0 / 899   <w:rPr with attributes
```

So **attribute tolerance is a theoretical difference on this corpus and
consolidating it would buy nothing.** The self-closing form is the one
Word really writes, and it is the one the package has already been bitten
by once (`PARA_RE`, fixed `6acc545`).

### 1a. `RUN_RE` has the `PARA_RE` defect → BACKLOG

`_xml.RUN_RE = <w:r\b[^>]*>.*?</w:r>` matches `<w:r/>` as an OPEN tag and
then runs on to the next run's close. Demonstrated on a paragraph holding
one empty run between two real ones:

```
visible text: 'The share rose to 0.15 in 2024.'
runs found by RUN_RE: 3          <- there are three real runs plus one empty
   run 1: '<w:r><w:t xml:space="preserve">The share rose to </w:t></w:r>'
   run 2: '<w:r/><w:r><w:t>0.15</w:t></w:r>'          <- two elements, one match
   run 3: '<w:r><w:t xml:space="preserve"> in 2024.</w:t></w:r>'
RUN_OPEN_RE matches: ['<w:r>', '<w:r/>', '<w:r>', '<w:r>']
```

`replace_in_para(para, "0.15", "0.17")` still produced the right text
here, and that is the point worth being careful about: **an empty run
contributes no visible text, so every OFFSET stays correct.** What is
wrong is run IDENTITY — the count, the boundaries, and which `w:rPr` a
walk believes belongs to a run. The consumers to audit are the fourteen
`RUN_RE`/`RUN_OPEN_RE` call sites in `_xml.editable_text`, `edit._locate`
(and `edit:384`), `equations:851`, `footnotes:227/276/480`,
`renumber:101`, `_cite_grammar:529/553`, `_table_layout:263/682`,
`_compare_read:128` — the property-reading ones first, since a merged
pair presents the EMPTY run's properties.

`crossrefs._P_OPEN_RE` (`<w:p\b[^>]*>`) is the pre-fix `PARA_RE`
spelling. It is latent rather than live: its one caller,
`_wrap_paragraph_in_bookmark`, is only ever handed a caption paragraph,
which has text. Worth fixing when the file is next open; not worth a
batch of its own.

**Suggested direction.** One element-pattern registry in `_xml`, and a
test asserting that no module outside `_xml` compiles a pattern beginning
`<w:`/`<m:` except on a named allowlist. That converts "22 elements have
several spellings" from a thing someone has to notice into a thing CI
notices. `ast-grep` (`sg run -p 're.compile($P)' -l python src/`) does
the census and the mechanical rewrite.

## 2. Public API nobody declared

Eleven modules define no `__all__` at all (`cli`, `compare`, and the nine
`_`-prefixed ones — defensible for the privates, less so for `compare`,
which is a facade, and `cli`).

Sixteen modules define one and leave public names out of it. With
`py.typed` in force, Pyright rejects every import of those names and
points the caller at a private module — the open S4 in `BACKLOG.md`, but
it is much wider than `visible_text`:

```
  revision.py    validate, moved_footnotes, restored_bookmarks, SAVE_NOISE, RESCUE_KEEP …
  crossrefs.py   link_more, DEFAULT_LABELS, LABEL_FORMS, NUMBER_END
  _xml.py        BOOKMARK_NAME_RE, HYPERLINK_ANY_RE, SECTPR_RE, WT_RE, MT_RE, dead_links …
  word.py        17 WD_* constants, CT_NS, PKG, FIND_LIMIT
  package.py     CORE_ORDER, CORE_PART        equations.py  EQ_NUMBER_RE, M_NS, XSL_ENV
  citations.py   repair_plan                  hygiene.py    CUSTOM_XML, NOTE_LEADS
  footnotes.py   SizeOutlier                  find.py       find_para
  authors.py     CORE_PART, PEOPLE_PART       body.py       DEFAULT_TBLPR
  lint.py        M, W, XML_SPACE              wordcount.py  APPENDIX_RE, REFERENCES_RE
  revisions.py   MATH, REVISION_RE, W, revision_elements
  tracked.py     MathOutcome, W               (mine, today)
```

`revision.validate` is the protocol's gate ladder — the headline function
of that module — and it is not exported. `crossrefs.link_more` is called
by **five** Parental_style scripts. So this is not a tidiness item: it is
the toolkit's real API, undeclared, and papers are already leaning on it.

**Suggested direction.** Fill the `__all__`s, then add one test that
walks every module and asserts "public name ⇒ declared", so the class
cannot come back. For the three facades (`citations`, `tables`,
`compare` — `citations.py` is 275 lines of which ~100 are `from _x import
y as y`), the same test should assert facade ⊇ submodule public names,
which is what a hand-maintained re-export list cannot promise.

## 3. Performance: one real hot spot, and it is not where the code worries

Profiled `compare` on a real pair (`LI7 prev.docx` → `working.docx`,
~1.1 M chars of `document.xml`):

```
  compare.load  (both documents)   278 ms
  compare_docs  (the comparison)    34 ms      <- 11 % of the work
```

Inside the load, pyinstrument over four iterations:

```
  2.178  Part.__init__            _compare_read.py:399
  1.171    Para.__init__          _compare_read.py:282
  0.940      _char_fmt            _compare_read.py:111      43 % of load
  0.410        _valued            _compare_read.py:95
  0.355          Cascade.of/explain/resolve      styles.py:208-247
  0.151            Cascade._chain → _val → re.search (recompiled per call)
```

`Cascade` is immutable after `__init__` and `resolve(prop, rpr, rstyle,
pstyle)` is a pure function of its arguments, called once per property
per RUN. Manuscripts repeat `w:rPr` strings in their thousands, so the
hit rate of a cache keyed on that tuple would be very high. `_val` builds
its pattern with an f-string and calls `re.search` on it per call, so
every lookup pays a pattern-cache probe.

Worth noting for context: `a87f201` (yesterday, the default-paragraph-
style fix) ADDED a lookup to this path for every paragraph that names no
style, which is most of them in a python-docx build. The fix is right;
the cost landed in the hottest function in the package.

**Suggested direction.** `lru_cache` on a private `_resolve(prop, rpr,
rstyle, pstyle)`, pre-compiled per-property patterns in `_val`. Low risk
— it is a pure function — and it should take most of that 0.35 s.
`pytest-benchmark` is now installed; pin the number before and after.

## 4. Layering: clean at the bottom, three cycles at the top

`grimp` over the package, direct imports:

```
  in  out   module
  33    0   _xml          <- the bottom, and it is a real bottom
  24    0   errors
   9    2   revisions          9   2  package        8   2  find
   2    9   tracked            1  25  cli            1   8  revision
```

Three mutually-reachable pairs — real cycles in the module graph:

```
  cli <-> compare        cli <-> revision        compare <-> revision
```

Each is broken at runtime by importing inside a function, which is why
`compare.py`, `cli.py` and `revision.py` all carry `PLC0415` per-file
ignores. That works, and it is deliberate (`import docxkit` must not pay
for lxml, pandas or pywin32). What is missing is anything that keeps the
rest of the layering true: the discipline lives in comments.

**Suggested direction.** An `import-linter` contract file, run in CI:

```ini
[importlinter]
root_package = docxkit

[importlinter:contract:layers]
name = docxkit layers
type = layers
layers =
    cli
    revision
    tracked | compare | export | wordcount
    citations | crossrefs | tables | comments | equations | footnotes
    edit | find | body | revisions | styles | package | hygiene
    _xml | errors

[importlinter:contract:facades]
name = the private halves are reached only through their facade
type = forbidden
source_modules = docxkit.export docxkit.renumber docxkit.refstyle
forbidden_modules = docxkit._cite_build docxkit._cite_grammar docxkit._table_core
```

(Sketch — the exact layer list wants one pass against the graph above.)
`tach` is the alternative and additionally enforces module INTERFACES,
which is the private-cross-import question in §7.

## 5. Complexity is unwatched on purpose, and it shows

`PLR0912` (branches), `PLR0913` (arguments) and `PLR0915` (statements)
are all in `ignore`, and `C901` (mccabe) is not selected. The reasons
given are good ones — XML passes are branchy, keyword options read better
than dicts — but the effect is that nothing at all watches size. radon
finds 27 functions above mccabe 10:

```
  E (31)  citations.repair_plan          D (24)  crossrefs.audit
  D (24)  cli.cmd_revision_validate      D (22)  footnotes.sizes
  D (21)  compare.compare_docs           D (21)  edit.replace_in_para
  D (21)  crossrefs.link                 D (21)  hygiene.restore_parts
```

and by line count: `cli.main` 289, `_cite_audit._audit_findings` 225,
`tracked.build` 224, `edit.replace_in_para` 177, `_cite_build.link_all`
168, `lint.lint` 154, `refstyle.audit` 143, `revision.build` 137.

**Suggested direction.** Not the ignores — a threshold. `select = C901`
with `max-complexity = 15` flags about ten functions, all of them ones a
reader would agree are large, and leaves the branchy-by-nature passes
alone. Two modules are the natural split candidates when they next need
work: `cli.py` (1,314 lines, 30 commands, fan-out 25) and `revision.py`
(1,224 lines carrying the Paper model, state machine, build, validate,
promote, baseline, ingest, rescue rotation AND the `log.md` /
`paper.toml` templates).

## 6. Duplication: almost none, and one real instance

pylint's `duplicate-code` over the whole package, 8-line window,
signatures and imports ignored: **nothing**. Dropped to 5 lines with
imports counted: exactly one hit.

```
docxkit._cite_grammar:[527:535]  ==  docxkit.edit:[162:171]

    runs, spans, cursor, prev_end = [], [], 0, 0
    for r in RUN_RE.finditer(para_xml):
        cursor += len(visible_text(para_xml[prev_end:r.start()]))
        body = visible_text(r.group(0))
        runs.append(r); spans.append((cursor, cursor + len(body)))
        cursor += len(body); prev_end = r.end()
```

This is the run-span walk, copied. `_cite_grammar` already imports
`edit._locate`, so the copy is not there for want of a route to the
original — and it is one of the fourteen `RUN_RE` walks from §1a, so
whatever is decided there has to be decided twice.

For a 19,000-line package built by accretion across nine manuscripts,
one duplicated block is a genuinely good result and worth saying so.

## 7. Privates crossing module lines

Established practice, unmanaged:

```
  _cite_grammar  <- edit._locate            _cite_repair <- edit._RUN_OPEN_RE
  _cite_build    <- _cite_audit._BOOKMARK_NAME_RE, _KEY_SHAPE_RE
  _table_core    <- revisions._has_revisions       equations <- revisions._fragment_declarations
  revision       <- tracked._paras, _root, _simulate     (mine, today)
```

Ruff's `PLC2701` does not flag these (it exempts intra-package relative
imports) and `SLF001` finds none, so no tool currently sees the pattern.
It is not wrong in itself — this is one package — but it means "private"
carries no information here, and a `py.typed` consumer cannot follow the
same route. `edit._RUN_OPEN_RE` is an alias of `_xml.RUN_OPEN_RE` and
`_table_layout._RUN_RE` an alias of `_xml.RUN_RE`, so two of these are
indirection through a module that adds nothing.

**Suggested direction.** Decide per name: promote to the public surface
of the module that owns it (`_locate`, `_has_revisions`), or move it down
into `_xml` where the sharing is legitimate. `tach`'s interface rules can
then hold the line.

## 9. Test suite: broad, and worth asking how deep

2,153 tests, ~20 s, 23,390 lines of tests against 18,856 of source — a
better ratio than most libraries manage, and the fixtures are synthetic
so the suite needs no Word.

Mutation testing (cosmic-ray, all 858 mutants of `revisions.py` against
its own three test files plus `test_tracked_build.py`):

```
  KILLED 707   SURVIVED 63   INCOMPETENT 88
  -> survival 63 / 770 competent mutants = 8.2 %
```

A survivor is a change to `revisions.py` that no test notices, and 8.2 %
is a good number — better than most libraries manage. It is better still
than it looks, because **about half the survivors cannot be killed by any
test**:

```
   6 x L120  return _NS + extra
   5 x L260  def _enclosing_math(el: Any) -> Any | None:      <- annotation
   5 x L322  def _mark_flag(para, tags) -> Any | None:        <- annotation
   4 x L507  def _simulate(xml, mode, where: Where | None)    <- annotation
   4 x L609  def accept(...)   4 x L624  def reject(...)      <- annotations
   2 x L652  @lru_cache(maxsize=8)                            <- RemoveDecorator
   2 x L368  for child in list(para):
   2 x L485  parent.remove(change)      # the live properties stay
```

`from __future__ import annotations` makes every annotation a string that
is never evaluated, so the 30-odd `ReplaceBinaryOperator_BitOr_*` mutants
rewriting `X | None` are equivalent mutants by construction; removing an
`lru_cache` changes speed, not results. Discount those and the real
survival rate is around 4 %.

**What to triage**, then, is short: the `_NS + extra` cluster at L120
(`_fragment_declarations` — six survivors on one line suggests the
non-empty-`extra` branch is not exercised), `for child in list(para)` at
L368 and `parent.remove(change)` at L485 in the property-revision pass.
That matters because `revisions.accept`/`reject` is the engine under the
reject-all gate that now blocks every redline.

**Operational hazard, worth recording.** cosmic-ray mutates the module
**in place in the working tree** while it runs, and docxkit is installed
editable — so for ~25 minutes any paper script importing docxkit could
have imported a mutant. Nothing was harmed here (`git status` verified
clean afterwards, full suite re-run green), but the next run belongs in
`git worktree add` copy with its own editable install, not in the live
tree.

Related: `pytest -m word` (8 tests) is the ONLY validation of the width
tables and is deselected from every ordinary run.

## Non-findings — measured, and not worth a batch

Recorded so the next reader does not re-derive them.

* **Repeated `read_parts` in the build flows.** `revision.build` reads
  `prev.docx` three times and `revised`/`out` once each; `tracked.build`
  reads the built package twice (once for the gate, once in `verify`).
  Measured: `read_parts` on LI7's 34-part, 2.5 MB package is **6 ms**.
  Five reads is 30 ms against a Word Compare that takes seconds.
* **The parse → serialise → re-parse round trip** in `untracked` and in
  `validate`: `revisions.reject` parses with lxml, serialises to a
  string, and `_root` immediately parses it again. Measured on LI7's
  1,870-revision redline: reject < 1 ms (it short-circuits), re-parse
  10 ms, whole `untracked()` **37 ms**. Architecturally redundant,
  practically free.
* **`lru_cache` keyed on megabyte strings** (`revisions._simulate_clean`
  maxsize 4, `_text_cached` maxsize 8, three in `crossrefs`). The
  comments already justify the sizes; CPython caches a str's hash, so
  repeat lookups are cheap. It is a memory-retention decision, not a
  time cost, and the sizes are small enough.
* **Attribute-tolerance divergence in the regex census** — 0 hits in 899
  manuscripts for every shape tested. See §1.
* **`except Exception`** — 11 in the package, 8 of them in `tracked`'s
  COM path and every one recorded into `report.suppressed` and printed.
  This is the documented pattern, not swallowing.
